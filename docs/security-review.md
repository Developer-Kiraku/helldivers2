# 로그인·개인정보 보안 점검 (2026-10-19)

범위: 카카오 OAuth, 임시 로그인, 세션, 가입 티켓, 회원 리스트, 회원 관리 API, 개인정보 응답, 이미지 업로드와 배포 의존성.

## 보완 사항

- 회원 목록과 관리자 작업 응답에서 카카오 식별번호와 승인 담당자 ID를 제외했습니다. 다른 회원의 임시 로그인 ID도 목록에 전달하지 않습니다. 본인의 내 정보에서는 본인 계정 정보를 확인할 수 있습니다.
- 임시 로그인은 운영 환경에서 기본 비활성화합니다. 운영용 신규 저장소의 기본 비밀번호는 임의 값이며 개발용 `1234`로 생성하지 않습니다. 운영 환경은 `DEMO_AUTH_ENABLED=false`를 유지합니다.
- 로그인 제한은 계정별 1분 8회, 전체 1분 100회입니다. 요청 헤더를 바꿔도 계정 제한을 피할 수 없으며 DB 트랜잭션으로 서버 간 동시 요청과 재시작을 처리합니다. 실패 기록에는 비밀번호·원문 아이디를 저장하지 않습니다. 존재하지 않는 계정도 비밀번호 해시 연산을 수행합니다.
- 세션 토큰은 256비트 난수이고 DB에는 SHA-256 해시만 보관합니다. 사용자별 최대 5개 세션을 유지하며 24시간 후 만료합니다. 쿠키에는 HttpOnly·SameSite=Lax를 적용하고 HTTPS/Render에서는 Secure를 강제합니다.
- 카카오 OAuth state는 서버에 해시와 10분 기한을 저장하고 외부 인증 교환 전에 한 번만 소비합니다. 신규 인증 시작 시 이전 가입 쿠키를 제거합니다.
- 회원 관리 API는 대상 존재 여부 확인 전에 운영진 권한을 확인합니다. 실제 등급 변경·강퇴·승인 권한은 서버에서 별도로 확인합니다. 기존 CSRF Origin 검사, 강퇴·탈퇴 시 세션 폐기, 익명 투표의 신원 비공개와 HTML 정리를 유지합니다.
- API 응답 캐시를 차단하고 SAMEORIGIN, nosniff, no-referrer, 불필요한 카메라·마이크·위치 권한 차단 및 프레임·폼·객체 정책을 설정했습니다. CSP는 일부 지시문만 적용하며 엄격한 스크립트 nonce 정책까지 구현한 것은 아닙니다.
- 요청 본문은 스트림을 읽는 동안 바이트 수를 제한합니다. 로그인 1KB, 가입 10KB, 닉네임 확인 1KB, 프로필 약 1.3MB, 일반 게시글 약 13MB입니다.
- 업로드는 브라우저에서 가로 최대 1,600px로 비율 유지 축소·압축합니다. 프로필은 최대 256px 정사각형입니다. 서버에서도 실제 디코딩·형식·해상도를 검증하고 다시 인코딩하여 메타데이터를 제거합니다. SVG·깨진 이미지·다중 프레임·6천만 픽셀 초과 이미지는 거부합니다. 외부 이미지 URL을 서버에서 가져오지 않습니다.

## 검증과 한계

검증 명령: `npm run build`, `npm run test:functional`, `npm run test:probation`, `npm run test:postgres`, `npm run test:postgres-http`, `npm run build:pages`, `npm audit --omit=dev`. 기능 테스트는 격리된 JSON, DB 테스트는 별도 임시 스키마를 사용합니다. 이미지 테스트는 실제 디코딩 후 가로 크기·비율·프로필 크기·투명도·메타데이터 제거를 확인합니다. 브라우저에서도 3,200×1,800 원본을 선택해 본문 첨부·사진 게시판에서 1,600×900으로 축소되는 것을 확인했습니다.

알려진 취약점 감사는 검사 시점의 패키지 데이터베이스에 한정됩니다. 이 점검은 모든 취약점의 부재나 외부 침투 테스트 수행을 의미하지 않습니다. 카카오 제공자와의 실제 사용자 로그인 완료는 별도 계정 상호작용이 필요하며 테스트에서는 제공자 인증 후 상태를 격리 DB에 구성합니다. 사용자 데이터가 있는 운영 DB를 초기화하거나 덮어쓰지 않습니다.

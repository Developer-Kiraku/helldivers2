# 인증·JSON 데이터 운영 안내

## 설정과 교체 지점

`.env.example`을 `.env.local`로 복사하고 실행 주소에 맞게 수정합니다. 서버를 재시작하면 반영됩니다.

| 설정 | 역할 |
| --- | --- |
| `DEMO_AUTH_ENABLED` | `true`: 요청한 네 임시 계정 로그인, `false`: 카카오 로그인만 제공 |
| `SEED_PASSWORD` | **새 JSON 파일 생성 시에만** 네 계정의 초기 비밀번호로 적용 |
| `JSON_DB_FILE` | 기본 `./data/db.json`, 운영 시 영구 디스크의 절대 경로 권장 |
| `APP_ORIGIN` | 브라우저 접속 출처. 프로토콜·호스트·포트를 정확하게 지정, 끝에 `/` 제외 |
| `COOKIE_SECURE` | 로컬 HTTP는 `false`, 운영 HTTPS는 `true` |
| `KAKAO_REST_API_KEY` | 카카오 앱 REST API 키. 클라이언트 공개 환경변수로 사용하지 않음 |
| `KAKAO_CLIENT_SECRET` | 카카오 앱에서 설정한 Client Secret |
| `KAKAO_REDIRECT_URI` | 카카오 앱에 등록한 `/api/auth/kakao/callback`의 전체 URL |

카카오디벨로퍼스에서 카카오 로그인을 활성화하고 웹사이트 도메인·Redirect URI를 실제 주소와 맞춥니다. 가입 흐름은 카카오 인증 → 서비스 필수 동의 및 닉네임 → 견습회원 가입입니다. 기존 회원은 카카오 인증 후 바로 로그인합니다. 카카오 사용자 번호만 저장하고 이메일·전화번호·카카오 프로필 정보는 요청하지 않습니다. 카카오 액세스 토큰은 사용자 확인에만 쓰고 DB에 저장하지 않습니다.

실제 카카오 인증은 앱 키와 앱 설정이 있어야 검증할 수 있습니다. 현재는 키 미설정 시 안내, 유효하지 않은 state, 카카오 인증 없는 가입 차단을 테스트했습니다. 카카오 앱의 외부 연결 해제 알림 처리와 서비스 탈퇴 시 카카오 연결 해제 API 호출은 추가 연동 범위입니다. 서비스 탈퇴는 서비스 계정을 정리하며 카카오계정 자체를 삭제하지 않습니다.

## 데이터 파일

서버가 처음 데이터를 요청할 때 파일이 없으면 네 계정과 게시판별 5개 예시 글, 예시 댓글을 생성합니다. 비밀번호는 scrypt 해시, 세션은 임의 토큰의 SHA-256 해시로 저장합니다. 로그인은 HttpOnly·SameSite=Lax 쿠키를 사용하며 세션 유효기간은 24시간입니다.

| 컬렉션 | 주요 내용 |
| --- | --- |
| `users` | 카카오 식별자, 로그인 ID·비밀번호 해시(임시 계정만), 등급, 닉네임, 사진, 상태, 최근 로그인·생성·수정일, 가입 동의 이력 |
| `posts` | 게시판·분류·제목·본문 HTML·본문 이미지, 작성자 ID, 생성·수정·삭제일 |
| `comments` | 게시글 ID, 작성자 ID, 댓글·작성일 |
| `votes` | 게시글 ID·회원 ID·추천/비추천. 회원당 게시글별 하나 |
| `requests` | 삭제/강퇴 요청 종류, 대상 ID·대상 정보, 요청자·사유·상태·처리자·처리 의견·처리일 |
| `sessions` | 해시된 로그인 토큰, 회원 ID, 만료 시각 |
| `pendingRegistrations` | 카카오 인증 후 가입 전 임시 티켓. 10분 만료 |
| `audit` | 로그인·계정 변경·삭제·강퇴·요청 처리 기록 |

본문 이미지는 에디터 안에서 넣고 JSON에 data URL로 저장합니다(개별 파일 최대 5MB, 본문 이미지 최대 5개, 전체 API 요청 최대 약 13MB). 프로필 사진은 브라우저에서 256px로 줄여 저장합니다. 일반 첨부파일 기능은 없습니다. 저장 시 서버에서 HTML·링크·이미지 형식을 검증합니다.

JSON은 단일 Node.js 프로세스 내 작업을 직렬화하고 임시 파일을 교체해 저장합니다. 서버 재시작·새로고침 후 유지됩니다. **여러 서버/프로세스에서 같은 JSON을 동시에 사용하지 마세요.** Render 등에서는 영구 디스크가 없으면 재배포 후 파일이 사라질 수 있으므로 `JSON_DB_FILE`을 영구 디스크에 지정해야 합니다. 정적 Netlify 시안과 달리 이 버전은 Next.js 서버 실행이 필요합니다.

MariaDB 등으로 바꿀 때는 `src/lib/server/store.js`의 `readStore`, `transaction`과 각 데이터 조회·변경을 DB 트랜잭션으로 옮깁니다. 인증과 API를 서버 폴더에 분리했지만 SQL 드라이버 연결만으로 자동 전환되는 구조는 아닙니다. 게시판 이름·최초 분류는 현재 `src/lib/data.js`, 권한은 `roles.js`와 `server/community.js`, 외부 채팅 링크는 `community-links.js`에서 수정합니다. 관리자 분류 편집 화면은 아직 없습니다.

## 권한과 상태

| 작업 | 운영자 | 부운영자 | 일반·견습회원 |
| --- | --- | --- | --- |
| 전체 사이트 열람 | 로그인 후 | 로그인 후 | 로그인 후 |
| 공지 작성 | 가능 | 가능 | 불가 |
| 공략·톡 작성 | 가능 | 가능 | 가능 |
| 본인 글 수정·삭제 | 가능 | 가능 | 가능 |
| 다른 사람 글 삭제 | 하위 등급 글 직접 삭제 | 일반·견습 글 요청 | 불가 |
| 회원 강퇴 | 부운영자 이하 직접 강퇴 | 일반·견습 강퇴 요청 | 불가 |
| 요청 승인·거부 | 가능 | 불가 | 불가 |
| 회원 등급 변경 | 부운영자·일반·견습 등급 변경 | 불가 | 불가 |

요청 승인 시 요청자와 대상의 현재 등급·상태를 다시 확인합니다. 중복 대기 요청과 재처리는 막습니다. 강퇴는 즉시 모든 해당 회원 세션을 취소하고 재로그인을 차단합니다. 탈퇴는 로그인 ID·비밀번호 해시·카카오 식별자·프로필 사진을 지우고 게시글 작성자를 ‘탈퇴한 회원’으로 표시합니다. 운영자는 직접 탈퇴할 수 없습니다. 운영권 이전 UI는 제공하지 않습니다.

서버를 정지한 상태에서만 JSON을 직접 편집하세요. 기존 파일 삭제는 모든 회원·글·요청 기록을 잃는 초기화이므로 먼저 백업해야 합니다. `SEED_PASSWORD`를 바꿔도 기존 회원 비밀번호는 바뀌지 않습니다. 임시 계정은 네 계정 모두 1234이므로 외부 서비스로 전환할 때는 `DEMO_AUTH_ENABLED=false`로 비활성화합니다.

## 검증

```bash
npm run build
npm run test:functional
npm run test:probation
```

통합 테스트는 `work/hd-functional-*`의 별도 JSON과 3150 포트를 사용하고 종료 시 테스트 폴더만 지웁니다. `data/db.json`은 사용하지 않습니다. `TEST_PORT` 환경변수로 포트를 바꿀 수 있습니다. 로그인, 페이지 이동 제한, API 권한 차단, 프로필 저장, 본문 정제, 투표·댓글, 요청 승인·거부, 강퇴·탈퇴 후 세션 차단, 동시 저장·중복 승인, 서버 재시작 후 유지까지 검증합니다.

약관·개인정보 문구와 운영 정보는 `docs/legal-review.md`의 운영 전 확정 항목을 참고해 실제 운영 내용으로 채웁니다. 임시 JSON의 감사·요청 기록과 백업 보관·삭제 일정도 운영 정책에 맞게 정해야 합니다.

## 견습회원 한 달 승인 정책

신규 견습회원의 기한은 가입 시각에서 **한국 시간 기준 달력으로 한 달 뒤 같은 날짜·시각**입니다. 다음 달에 해당 날짜가 없으면 말일로 정합니다(예: 1월 31일 → 2월 28일/29일). 정확한 기한부터 미승인 계정의 접근을 차단합니다.

운영자와 부운영자는 회원 리스트에서 ‘견습회원 승인’을 누르면 일반회원으로 전환할 수 있습니다. 승인 시각·승인자 ID를 기록하며 승인된 일반회원은 자동 탈퇴 대상에서 제외합니다. 운영자가 등급 변경으로 견습회원을 일반회원 이상으로 올리는 경우에도 승인 이력을 기록합니다. 일반회원·견습회원의 승인 요청과 이미 만료·탈퇴한 계정의 승인은 서버에서 차단합니다.

회원 리스트와 내 정보에 승인 기한을 표시하고 가입 화면에도 자동 탈퇴 정책을 안내합니다. 만료 시 일반 탈퇴와 동일하게 카카오 식별자·로그인 ID·비밀번호 해시·프로필 사진을 지우고, 작성자 표시를 익명화하며 모든 세션을 취소합니다. `withdrawalReason=probation_expired`, `withdrawnAt`과 `user.withdraw.probation_expired` 감사 기록이 남습니다.

Node 서버 시작 시 및 **매 1분마다** 만료 계정을 정리합니다. 모든 데이터 요청 전에도 같은 정리를 실행하므로 만료된 세션으로 접근하거나 기한을 넘겨 승인할 수 없습니다. 실패한 API 요청에서도 만료 처리는 저장됩니다. 서버가 정지·절전된 동안에는 작업할 수 없으며, 재가동 시 누락분을 바로 처리합니다. 이 기능은 현재 단일 Node 서버 프로세스에서 실행되며, 요청 때만 실행되는 서버리스 환경으로 옮길 때에는 별도 서버 스케줄러가 필요합니다.

기존 JSON에 기한이 없는 견습회원도 **기존 생성일**을 기준으로 한 달 기한을 보완합니다. 이미 한 달이 지난 기존 견습회원은 다음 서버 구동/조회 시 자동 탈퇴 대상입니다. 일반회원에서 견습회원으로 변경하면 변경한 시각부터 새 한 달 유예기간을 시작합니다. 기존 견습 등급을 그대로 저장하는 것만으로 기한을 연장하지 않습니다.

`test:probation`은 달력·윤년·한국 시간 경계, 승인 권한과 중복 승인, 등급 재변경, 기존 데이터 보완, **HTTP 요청이 없는 상태의 실제 분 단위 자동 처리**, 실패 요청 후 만료 저장·세션 취소를 별도 JSON으로 검증합니다. 실제 타이머를 기다려 약 1분 이상 걸립니다.

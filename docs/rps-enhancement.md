# 가위바위보 손 강화

기본 승리·무승부·패배 확률은 각각 1/3입니다. 계정당 손 하나를 0~20강까지 강화하고 가위·바위·보 모두에 적용합니다. 1~5강은 단계당 0.5%p, 6~10강은 1%p, 11~20강은 1.5%p를 패배 확률에서 승리 확률로 누적해서 옮기며, 무승부는 1/3을 유지합니다. 20강의 누적 증가분은 22.5%p로 승리 55.833…%, 무승부 33.333…%, 패배 10.833…%입니다. 서버는 600개의 균등한 난수 구간으로 정확하게 판정하며 승리 배율 추첨은 기존 설정을 유지합니다. 새 승부부터 현재 강화 단계에 맞는 확률이 적용되고, 이미 처리한 승부의 재요청은 원래 결과를 유지합니다.

단계 이름·비용·성공률·실패 하락은 `src/lib/rps-enhancement.mjs`, 승패 확률은 `src/lib/rps-rules.mjs`를 서버와 화면이 공유합니다. 1~10강 성공률은 100/95/90/85/80/76/72/69/66/63%입니다. 10→11강은 60%이고 이후 4%p씩 감소하여 11~20강 목표 성공률은 60/56/52/48/44/40/36/32/28/24%입니다. 비용은 50P부터 단계마다 25P씩 증가하여 10강 도전은 275P, 20강 도전은 525P입니다. 강화 화면은 승패 증감값 대신 다음 강화의 성공 확률을 표시하며, 확률표는 현재→목표 단계로 표기합니다.

실패 규칙은 **도전 목표 단계 기준**입니다. 목표 +1~5는 현재 단계 유지, +6~10은 현재 단계에서 -1, +11~20은 -2입니다. 따라서 5→6 실패는 4강, 10→11 실패는 8강입니다. 성공과 실패 모두 비용을 쓰며 현재 포인트만 차감하고 누적 포인트·가위바위보 도전 횟수는 바꾸지 않습니다.

`/api/games/rps/enhance`의 GET은 자신의 손과 요청 ID별 영수증을 읽고 POST는 강화합니다. 요청 ID로 재시도 중복 차감을 막고 `expectedVersion`으로 여러 탭의 오래된 요청을 거절합니다. 서버가 단계·비용·성공률·난수를 결정하며 클라이언트의 결과 필드는 사용하지 않습니다. 유저 `rpsHand`와 포인트 원장, `rpsEnhancements` 영수증을 같은 트랜잭션에 저장합니다. PostgreSQL의 `hd_rps_enhancements` 테이블은 기존 자동 마이그레이션으로 생성합니다.

강화 팝업은 처리 중 닫힘과 중복 클릭을 막고, 응답 유실 시 같은 ID로 결과를 다시 조회합니다. 단계별 SVG 손 문양·색·룬 개수·광량과 성공/실패 효과를 사용하고 모션 감소 설정을 따릅니다.

검증: `test-rps-game.mjs`, `test-rps-enhancement.mjs`, `test-rps-ui.mjs`, `test-rps-enhancement-http.cjs`. 전체 기능 검증에도 포함됩니다.

성공 연출은 서버의 성공 응답을 받은 뒤 재생합니다. 1~4강 민트 섬광, 5~9강 청록 파동, 10~14강 보라 광선, 15~19강 주황 폭발, 20강 금색 효과로 구분하며 단계별로 파티클 수·거리·잔광이 커집니다. 모션 감소 설정에서는 움직임 없이 색상·테두리·성공 문구로 표시합니다.

손 그림은 `src/lib/hand-artwork.mjs`의 공통 SVG로 화면과 공유 PNG에서 같은 좌표·단계별 색·룬·광륜·발광 효과를 사용합니다. 공유 카드는 성공 후 잔광 상태를 정지 이미지로 담으며, 손을 왼쪽에 두고 오른쪽에 강화 수치·이름·닉네임을 표시합니다. 손 공유 이미지 주소에는 렌더링 버전이 붙어 이전 그림의 캐시를 갱신합니다.
